# Completion Backlog (audit of 2026-09-05)

Audited: `apps/backend`, `apps/mobile`, `apps/backend/prisma` + `supabase/migrations`, CI and the GitHub scheduler, against BRD v2.1, on `master` (HEAD `7e3452f`, clean tree; every `file:line` below re-checked against that commit).
Four reviews fed this: backend wiring (BW — booted `AppModule` in fake mode and drove cron/reply/cascade/webhooks with curl), backend robustness (RB — 36 findings), mobile wiring (MW — every route and backend call), BRD coverage (BRD — 112 rows: 20 done, 65 partial, 21 missing).
Verdict: the DI graph, data layer, consent gate and cascade state machine are real, but the safety loop cannot reach a human today — HELP escalation 500s on the audit PII guard, cascade exhaustion notifies nobody, SMS bodies are raw template keys, the fake reply route is open to the internet, and the app is not store-buildable.
How to use: work top to bottom; do not open a lower phase while a higher phase has undone items (founder decisions excepted). Paths are relative to `apps/backend/src/` unless prefixed `apps/mobile/` or `prisma/`.
An item is done only when its "Done when" line is observably true AND the named spec exists and passes in CI. Size: S ≤ half a day, M ≤ 2 days, L > 2 days.
IDs are stable and never reused; new findings get the next free ID at the end of their phase. Sources use `BW#n` (wiring blocker n or row name), `RB-xx` (robustness finding), `MW#n` (mobile blocker/section), `BRD-x` / `FR-xxx` (coverage matrix row).

Contradictions resolved by reading code: (1) RB-H3 proposes calling `escalateMissedCheckIn` on exhaustion; that method fans out to backup contacts (`escalations.service.ts:111-128` → `escalateBackupContacts`), which BRD FR-BAK-03 reserves for the sender's choice — BW#2/BRD-1 are right: notify the sender only (CB-005). (2) BRD marks FR-AUTH-02 "Done (unverified)"; MW#3 is right — `apps/mobile/src/services/auth.ts:113-125` stores an expected `state` and `supabase.ts:106-111` rejects any callback without it, and GoTrue never echoes a client `state` on the PKCE `?code=` redirect (CB-028). (3) BW cites `pauseForAbuseReview` at `:369-378`; the code is at `prisma-receivers.repository.ts:370-379` (cosmetic).

## Already solid, do not redo

- Cron secret and Twilio HMAC signature checks are timing-safe and fail closed (`operations.controller.ts:86-103`, `provider-webhooks.controller.ts:324-360`); tampered bodies rejected in curl.
- Object-level authorisation in every query (`userId` in every `where`; backup contacts verify receiver ownership; admin roles per route).
- Step-up design: hashed OTP and token, 10-minute TTLs, 5-attempt lock, single-use, action-bound.
- Env validated with zod at boot; KMS key length checked; no `process.env` reads outside config.
- AES-256-GCM with a fresh IV per value on email/phone/name/notes/transcripts/report content; audit table append-only via DB triggers, verified by `check-invariants` in CI (12 checks, 630 assertions, RLS on 124 tables).
- RevenueCat idempotency via `idempotency_keys` and P2002 handling; subscription upsert keyed by external id.
- Account deletion runs as a single transaction anonymising user, receivers and backup contacts.
- Helmet, global throttler, CORS allow-list, configurable `trust proxy`; webhooks and cron explicitly skip throttling.
- DI graph boots clean (14 modules, 39 routes); Prisma repositories bound in every module; migrations equal the repo.
- Twilio request shapes (Messages.json, Calls.json with AMD/StatusCallback params, TwiML Gather) are correct and asserted by `configured-channel-providers.spec.ts`.
- Mobile REST contract matches the backend field-for-field; no direct Supabase table access from the app; enum alignment compile-checked.
- Consent gate (no check-in before YES), positive reply closes silently and cancels pending attempts, ≤ 5 backups, three tech profiles — all Done with specs.
